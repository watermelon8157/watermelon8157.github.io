# Repository Memory

## Stable Context
- **Repository**: `watermelon8157/watermelon8157.github.io`  
- **記憶維護流程**  
  - 由每日的 *issue agents* 產出 snapshot，彙整當天活躍的 Issue。  
  - 只要 Issue 存在，系統會自動抽取跨 Issue 主題、決策與未完成事項。  
  - 若當天無可用 Issue，則保留先前已建立的長期記憶，不會產生新條目。  
- **手動筆記 (`shared/manual.md`)**  
  - 用於保存 **穩定規則、長期決策、常見限制** 以及 **repo 習慣**。  
  - 此檔案不會被自動覆寫，僅供 agents 參考。  
- **目前觀測到的穩定事實**  
  - 沒有任何跨 Issue 主題、決策或新開放的 Loop 在過去 7 天內被偵測到。  
  - 系統在缺乏 Issue 時會「先保留既有記憶」，表示已有的長期記憶不會因為空白日誌而遺失。

## Recent Themes
> 近期（過去 30 天）未出現可辨識的跨 Issue 主題或重複出現的討論焦點。  
> 若未來出現持續性的議題，將在此區塊列出。

## Constraints
- **資料來源限制**：目前的每日快照皆顯示「本次整理視窗沒有可用 issue」，因此缺乏新資訊供分析。  
- **更新頻率**：只有在 Issue 有變動（新增、更新、關閉）時，才會產生可供蒸餾的內容。  
- **不確定性**：因為缺少 Issue，無法確認是否存在隱藏的長期需求或限制。  
- **手動筆記依賴**：所有穩定規則與限制必須由人類在 `shared/manual.md` 中手動維護，系統不會自動推斷。

## Open Loops
- **等待 Issue 更新**：所有每日快照皆顯示「等待下一輪 issue 更新後再整理」，因此目前沒有具體的未完成事項。  
- **潛在需求**：若未來出現新 Issue，需檢視是否形成以下類型的開放迴路：  
  1. 新功能需求或改版計畫  
  2. Bug 修復或技術債務  
  3. 文檔或流程優化建議  
- **資訊不足**：目前無法確定是否有隱藏的長期目標或未完成的決策，需待 Issue 流入後再行評估。
