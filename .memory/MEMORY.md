# Repository Memory

## Stable Context
- **資料來源原則**：所有可追溯的事實與決策必須以 GitHub Issue 或 Comment 為唯一原始依據，手動筆記僅作為摘要與指引，**不會**直接覆寫原始 Issue 內容。  
- **記憶工作流程**：`compact‑memory` 工作流會在每日快照後讀取本手動筆記，以補足缺失的長期規則與限制，並將其納入長期記憶庫。  
- **Repo 共同慣例**：  
  1. 每日由多個 *issue agents* 產出快照，彙整當天活躍 Issue。  
  2. 若當天無可用 Issue，則保留既有記憶，不新增或刪除條目。  
  3. 跨 Issue 的主題、決策與未完成事項會在有足夠證據時由龍蝦群抽取並歸類。  

> **不確定性**：目前尚未觀測到任何具體的穩定規則、長期決策或常見限制，以上條目僅根據手動筆記的流程說明推測為「穩定」的運作方式。

## Constraints
1. **Issue 依賴**：所有記憶條目必須能追溯至 Issue 或 Comment；若缺乏此類來源，條目將被視為暫時性資訊，僅放於「Open Loops」或「Recent Themes」。  
2. **手動筆記不可覆寫**：`compact‑memory` 流程只能讀取 `shared/manual.md`，不會對其內容進行寫入或修改。  
3. **每日上限**：每次快照最多處理 100 個 Issue，且僅限最近 30 天內的變動。  
4. **標籤依賴**：若未出現任何標籤（Top Labels 為 `none`），則視為無可分類資訊。
