# Repository Memory

## Stable Context
- **資料來源原則**：所有可追溯的事實與決策必須來自 GitHub Issue 或 Comment，手動筆記僅作為摘要與補充，且不會被自動流程覆寫。  
- **記憶維護流程**：每日快照會由各 Issue Agent 彙整，若當日無可用 Issue，則保留既有記憶，不產生新條目。  
- **手動筆記規範**：`shared/manual.md` 只應保存 **穩定規則、長期決策、常見限制與 repo 習慣**，不應直接複製 Issue 原文。  

> **不確定性**：目前的快照皆顯示「本次整理視窗沒有可用 issue」，因此無法從近期資料抽取其他長期規則或決策。

## Recent Themes
- **無可辨識跨 Issue 主題**：過去七天（2026‑03‑27 至 2026‑04‑02）皆未出現可供分析的 Issue，故未形成重複或新興主題。  
- **持續的空白狀態**：每日快照均報告「先保留既有記憶」，顯示 repository 在此期間未有活躍的 Issue 流程。

## Constraints
1. **不允許直接複製 Issue 內容**：所有自動生成的記憶必須以摘要形式呈現，避免冗長與版權問題。  
2. **手動筆記不可被自動覆寫**：`shared/manual.md` 只作為人類編輯的長期記憶來源，系統不會改寫此檔。  
3. **Issue 數量上限**：每日快照僅檢視最近 30 天內、最多 100 個 Issue；若超過此上限，將僅取前 100 個。  
4. **決策與主題必須具備跨 Issue 證據**：單一 Issue 無法直接升格為「穩定規則」或「跨 Issue 主題」，除非在多個 Issue 中重複出現。

## Open Loops
- **等待新 Issue**：目前所有快照皆顯示「等待下一輪 issue 更新後再整理」，因此所有未完成的追蹤項目皆掛在此待命狀態。  
- **未確定的長期規則**：若未來出現持續出現的 Issue（例如部署流程、代碼風格等），需重新評估是否納入 **Stable Context**。
