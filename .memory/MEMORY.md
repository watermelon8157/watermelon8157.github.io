# Repository Memory

## Stable Context
- **資料來源**：長期記憶的唯一正式來源是 GitHub Issue 與 Comment，所有可追溯的事實與決策必須以這些原始資料為依據。  
- **手動筆記**：`shared/manual.md` 只用來保存 **穩定規則、長期決策、常見限制** 以及 **repo 內部慣例**，不會被自動覆寫，也不應直接複製 Issue 原文。  
- **工作流程**：  
  1. **Issue 產生** → 代理人（agents）每日抓取當前開放的 Issue。  
  2. **每日快照** → 產出 `daily/YYYY-MM-DD.json`，彙整當天可見的跨 Issue 主題、決策與未完成事項。  
  3. **記憶蒸餾** → 龍蝦群將每日快照中重複出現的資訊提煉成長期可重用的上下文（本文件）。  
- **目前狀態**：過去 30 天內的所有快照皆顯示 **「本次整理視窗沒有可用 issue」**，因此尚未形成任何可視為「穩定」的規則或決策。

## Recent Themes
> 近期（過去 30 天）未偵測到任何跨 Issue 的共通主題。  
> 若未來出現持續出現的議題（例如：部屬流程、內容更新頻率等），將在此區塊列出。

## Constraints
- **資訊完整性**：除非 Issue 被明確關閉或標記為已解決，否則其內容仍被視為活躍資訊，不能自行刪除或忽略。  
- **手動筆記的限制**：`shared/manual.md` 只能由人類手動編輯；自動化流程（包括本記憶蒸餾）不會寫入或修改此檔。  
- **缺乏資料**：目前沒有可用的 Issue，導致無法驗證或建立任何新規則。所有推論皆基於「無資訊」的前提，需在未來有 Issue 出現時重新評估。

## Open Loops
- **等待 Issue 更新**：所有每日快照皆顯示「等待下一輪 issue 更新後再整理」，表示目前缺乏可供分析的原始資料。  
- **未確定的長期規則**：因為缺少實際案例，無法確定任何潛在的長期規則（例如：發布頻率、內容審核流程）。  
- **未完成的手動筆記**：`shared/manual.md` 仍是空白
