# Repository Memory

## Stable Context
- **Repository**: `watermelon8157/watermelon8157.github.io`（個人網站的 GitHub Pages 專案）。  
- **記憶維護機制**：每日由 *issue agents* 讀取過去 30 天內的 Issue，彙整成快照（`daily/*.json`），再由龍蝦群（本記憶系統）抽取長期規則與共識，寫入本檔。  
- **手動筆記**：`shared/manual.md` 為人類手動維護的長期記憶，僅保存 **穩定規則、長期決策、常見限制、repo 習慣**，不會被自動流程覆寫。  
- **工作流程**：  
  1. **Issue 產生** → agents 監測並產出每日快照。  
  2. **快照分析** → 若出現跨 Issue 主題或決策，會被蒸餾至本檔的相應章節。  
  3. **手動筆記** → 人類可自行在 `shared/manual.md` 補充未被自動偵測的長期資訊。  
- **目前狀態**：過去 7 天（2026‑04‑02 ~ 2026‑04‑08）皆未偵測到可用 Issue，故沒有新增的跨 Issue 主題、決策或標籤。

## Recent Themes
> **無**：在最近的每日快照中未出現任何可辨識的跨 Issue 主題或重複出現的議題。若未來出現新 Issue，相關主題將在此區塊更新。

## Constraints
1. **不複製原始 Issue 文字**：所有自動生成的內容必須是抽象化、概念化的描述，避免直接貼上 Issue 內容。  
2. **保留手動筆記**：`shared/manual.md` 只作為參考，系統不會覆寫其中的文字。  
3. **語言與語氣**：必須使用繁體中文，語氣模擬「龍蝦」在替主人記憶，仍保持工程可讀性。  
4. **資訊完整性**：若資訊不足或相互矛盾，必須在本檔明確標示「不確定」或「缺乏資料」。
